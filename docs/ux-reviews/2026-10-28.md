Revision: `357cfd6`. Device: disposable iPhone 17, iOS 27.0.

The app launched successfully after the user-approved signing correction. The user
signed in directly. Reviewed the Library landing page, movie grid and filters,
movie details, Discover connection gate, Library/Catalog search modes, Downloads

## Observed UX feedback

Prioritize R06, R07, and R08 first. R02, R04, and R05 are polish improvements.

| ID | Priority | Observation | Suggested change |
| --- | --- | --- | --- |
| R01 | P2 | Home names the installed app Seer, while onboarding says "Welcome to Flowmark". | Use one product name across the icon, welcome screen, and permission explanations. |
| R02 | P3 | Add Server introduces an "internal address" before sign-in, while the only URL example is HTTPS. | Focus on the Jellyfin address, show HTTPS and LAN examples, and move address-switching details to network settings. |
| R03 | P2 | The first-run Library tip says the library is syncing and directs users to Discover. Discover immediately requires another service connection. The tip remains visible even with library content loaded. | Make the tip reflect actual sync state and Jellyseerr availability. Offer a useful Library action when Jellyseerr is unconfigured. |
| R04 | P3 | Empty Downloads says downloaded media will appear here, without explaining how to start a download. | Add a Browse Library action and a short instruction to open a title and choose Download. |
| R05 | P3 | The optional setup sheet title truncates to "Connect Jell…" at default iPhone text size. | Shorten the navigation title or cancellation label so the service name stays readable. |
| R06 | P2 | In movie details, Download wraps as "Down-" / "load" at default text size. The button becomes taller than the adjacent Resume action. | Give both actions sufficient width or stack them at narrow widths. Keep action labels intact. |
| R07 | P2 | The movie community-rating star is exposed as an image named "Favourite", followed by the numeric score. | Hide the decorative star and combine the score into an explicit label such as "Community rating, 7.3 out of 10". |
| R08 | P2 | The Storage Limit slider has no accessible name and exposes "0%", while the visible value is Unlimited. | Name the slider Storage Limit and expose Unlimited or the selected GB value rather than a percentage. |

## What worked

The welcome screen gives a clear primary action. Add Server disables Continue
while empty. Movie navigation and the Favorites filter worked; the empty filter
state retained the controls needed to recover. Library search and Catalog have
separate scopes, with a clear Jellyseerr connection explanation for Catalog.
The privacy page explains diagnostic categories, retention, and the installation
identifier. Download actions expose a useful accessible name, state, and hint.

## Follow-up checks

These are source observations, not runtime-confirmed defects.

- `OnboardingViewModel.validateManualURLAndAdvance` rejects bare hostnames and
  IP addresses without a scheme. Check the error and recovery with a LAN address.
  The current message is "Please enter a valid URL (https://...)".
- `ServerInfoFetcher` presents HTTP failures as "Network error: HTTP 404" or
  another status number. Check whether users get enough advice to correct an
  address or reverse-proxy base path.

Existing items in [the UX review backlog](../ux-review-backlog.md) retain their
current status. This review does not reopen completed items.

## Review environment

Used a temporary source copy, empty `Config/Secrets.xcconfig`, separate package
checkouts and DerivedData, and a disposable simulator. No existing app accounts
or production credentials were used during setup.

The initial unsigned build passed but crashed during CloudKit initialization.
Its log explicitly reported a missing `com.apple.developer.icloud-services`
entitlement. This was a review setup error, not a product UX defect.

The user approved signing the temporary app with its existing entitlements.
Manual ad-hoc signing passed signature verification but failed to launch. A cached
Xcode build with the following overrides passed and generated the simulator
entitlement metadata and local signatures:

```text
CODE_SIGNING_ALLOWED=YES
CODE_SIGN_IDENTITY=-
CODE_SIGN_STYLE=Manual
PROVISIONING_PROFILE_SPECIFIER=
```

An in-place replacement installation stalled. A clean uninstall/reinstall on the
disposable device completed, and the app reached onboarding. The authenticated walkthrough is complete. Cleanup removes only this review's
temporary build outputs and disposable device.

The simulator also froze during setup. Device Hub keyboard capture was enabled,
and restarting only the disposable device restored input. Host load averages
ranged above 350 and briefly exceeded 700. Setup delays are not reliable evidence
of app performance.
